# 전체 리뷰 — 2026-09-26

중점(요청): 포커 게임 로직 / 웹 전반 / 승률·에퀴티 계산(로직·프로세스 오류, 효율성·방법론).
리뷰어 4명 병렬(읽기 전용): R1 게임 로직 · R2 웹 · R3 에퀴티 정확성 · R4 에퀴티 효율·방법론+DB. 메인 세션이 치명·높음을 코드로 재확인.

## 인터뷰 (공통 전제)
- 성공 기준: ① 봇이 쓸 만한 상대 ② 힌트·평가를 믿을 수 있음 ③ 게임이 정확·쾌적 ④ 혼자 오래 유지 가능
- 불안한 점: 에퀴티 숫자가 맞나 / 계산이 느리고 DB가 큼 / 게임 진행 버그
- 제외(문제 제기 불필요): 로컬 전용·보안, 100bb 고정 근사, 모바일 미대응

## 한 페이지 결론

1. **에퀴티 숫자는 헤즈업에서 정확하다.** 독립 구현(코드 공유 없음)과 대조해 평가기 12만 쌍, 리버·턴 전수값, DP, 실 DB exact 행 76개가 모두 완전 일치했다. 프리플랍 845행도 알려진 값과 ±0.12%p 이내다. 틀리는 곳은 숫자 계산이 아니라 **멀티웨이 동률(항상 1/2로 셈)** 과 **에퀴티를 결정으로 바꾸는 곳(숏스택 콜 EV·팟오즈 미캡)** 이다.
2. **15GB DB의 정체는 "재사용되지 않는 리버 DP 부산물"이다.** 행의 97.3%(1억 3,600만)가 리버 vs1 exact이고, 거의 전부 07-07~07-10 사흘 그라인드로 쌓였다. 게임에서 같은 리버를 다시 만나는 비율은 0.06%, 캐시가 아껴 주는 시간은 판단당 수 ms다. 키가 턴/리버 순서를 보존해 절반가량은 같은 값의 중복이다. **캐시를 없애고 실시간 계산(MC + 리버 3ms 전수)으로 가도 정확도·체감 속도가 거의 그대로**라는 측정이 나왔다 → 사람 결정(D-23).
3. **게임 버그는 "웹 세션이 엔진 룰을 따로 다시 구현했고, 테스트는 엔진만 검사한다"는 한 가지 구조에서 나온다.** 헤즈업 프리플랍에서 BB가 먼저 행동하고, 콜도 못 채운 올인이 액션을 다시 열고, 파산 뒤 버튼이 건너뛴다. 테스트와 spec의 "강제 장치"는 실제 사람이 치는 경로를 보지 않는다. 반면 칩 보존·사이드팟 분배·핸드 평가는 3,150핸드 퍼징과 6만 핸드 대조에서 튼튼했다.
4. **웹은 API 경계에 방어가 없다.** "다음 핸드"를 두 번 누르면 칩이 사라지고, 봇 예외 한 번에 세션이 멈추고, 동시 요청이 이벤트를 가로챈다. 프론트는 재생 중에 최종 상태(팟·스트리트·에퀴티)를 먼저 보여주고, lint 38건 오류와 테스트 0개로 품질 게이트가 없다. 응답 지연은 측정상 문제없다(hard p90 0.14초).

- 풀 레이즈 올인이 `min_raise` 미갱신(`core/game.py:204-212`), 스택 초과 레이즈가 유령 `current_bet` 생성(`:189-198`) · 중간

### RC5. 에퀴티 캐시가 목적·필요 정밀도·재사용률 측정 없이 확장됐다
- 리버 1억 3,600만 행 = 재사용 안 되는 플랍 DP 부산물(플랍 1개당 2,053행, 재방문 0.06%). DP는 직접 열거보다 2배 느리고 2,209배 많은 행 — `equity_worker.py:715-763` · 높음. ADR 0018 "메모 테이블" 전제가 실측과 반대
- 성장 원인은 스윕이 아니라 "게임에서 만난 모든 스팟 × DP 부산물"(스윕분 ≤1.7%). 대기 플랍 91,739개를 현 방식으로 끝내면 +17GB·171 CPU시간. D-12의 전제("매일 밤 커진다")·선택지가 원인을 비껴감 · 높음
- 워커는 런타임이 이미 exact와 동급으로 믿는 MC 20k(0.14초, 오차 0.2%p) 대신 48배 비싼 exact를 계산 · 높음
- 키가 턴/리버 순서 보존 → 같은 값 중복(리버 약 2배, R3 표본 63%) — `equity.py:55-72` · 높음(용량) · **R3+R4 교차, 재확인함**
- TEXT 키 + UNIQUE 인덱스 사본 + `updated_at`이 용량 절반 이상. freelist 0이라 VACUUM만으로는 회수 없음 · 중간
- 증분 통계 드리프트 실재(river +10/+1,480, turn +40) — 전 상태 SELECT가 트랜잭션 밖. ADR 0021 "드리프트 없음" 거짓 · 중간 · R3+R4 교차
- 멀티웨이 샘플 누적(61억 샘플)이 재방문 0~6%의 스팟에 CPU 소모, 그라인드 재가동 시 디스크 가드 없음(0.4~1.8GB/시간), 비용 주석이 실측과 10~100배 다름(리버 "<1초" → 3ms) · 중간~낮음
