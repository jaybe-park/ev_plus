# 0022. equity_cache는 재계산 가능한 캐시로 유지, vs_random은 계산만 유지하고 UI에서는 뺀다

- 상태: 유효
- 날짜: 2026-07-17 · 결정자: jaybe-park

## 맥락
equity_cache는 "vs 랜덤 핸드" 기준이라 3벳팟처럼 상대 레인지가 좁은 상황에서는 쓰레기 핸드까지 포함한 과대 equity를 준다. 레인지 기반 equity(`ranged_equity`)가 생기면서 "캐시를 없애도 되나", "패널에 두 값을 다 보여줄 필요가 있나"가 문제가 됐다. 동시에 DB가 커져 캐시의 존재 이유를 다시 확인할 필요가 있었다.

## 결정
- equity_cache를 삭제하지 않는다. 레인지 계산은 캐시를 쓰지 않으므로([0017](0017-equity-canonical-key-exact-protection.md)) 경로가 겹치지 않고, vs_random은 easy·medium 봇과 hard 봇의 레인지 정보 없는 경우(폴백)에 계속 쓰인다. 캐시는 언제든 다시 계산할 수 있는 파생 데이터로 취급한다(원본 데이터가 아니다).
- 에퀴티 패널에는 vs_range만 보여 준다. vs_random은 서버에서 계속 계산하지만 UI에 표시하지 않는다.
- 캐시 크기 상한·정리는 DB 인프라 작업에서 따로 다룬다.

## 버린 대안
- equity_cache 삭제 — 봇 런타임 폴백과 워커 정확값이 사라진다.
- 패널에 두 값 모두 표시 — 무엇을 믿어야 하는지 헷갈린다(사용자 피드백).
