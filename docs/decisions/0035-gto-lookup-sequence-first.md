# 0035. GTO 조회는 액션 순서 키 먼저, 간단 라벨은 "근사" 예비

- 상태: 유효
- 날짜: 2026-09-26 · 결정자: jaybe-park
- 대체: [0006](0006-enum-first-and-model-guards.md)의 조회 순서 부분(데이터 모델 밖 가드는 유효)

## 맥락
ADR 0006은 기존 봇·테스트를 깨지 않으려고 간단 라벨(포지션·상대·상황 종류) 조회를 먼저, 액션 순서 키를 예비로 두었다. 간단 라벨은 콜러를 구분하지 못한다. 그래서 두 가지 문제가 생겼다.
- 헤즈업 팟과 멀티웨이 팟이 같은 데이터를 받는다.
- 정확한 노드가 수집돼 있어도 쓰이지 않는다.

저장을 액션 순서 키 기준 유일로 고치면(T-001), 간단 라벨 하나에 노드가 여럿 생겨 라벨 조회 결과도 모호해진다.

## 결정
게임 중 GTO 조회는 다음 순서로 한다.
1. 액션 순서 키로 정확한 노드를 찾는다(사이즈 스냅은 ADR 0010).
2. 없을 때만 간단 라벨로 찾는다. 라벨 하나에 노드가 여럿이면 **콜러가 없는 노드**를 쓴다. 이 결과는 힌트·평가에 "근사"로 표시한다.
3. 둘 다 없으면 None — 힌트 없음, 봇은 휴리스틱을 쓰고, 미수집 큐에 기록한다.

데이터 모델 밖 상황 가드(BB RFI 불가 등, 0006)는 그대로 적용한다.

## 버린 대안
- 간단 라벨 먼저 유지 + 대표 노드 고정 — 수집된 정확한 데이터가 계속 무시된다.
- 간단 라벨 조회 폐기(액션 순서 키만) — 원칙상 가장 깔끔하지만, 수집 58노드인 지금은 힌트 공백이 크다. 수집이 충분히 쌓이면 이쪽으로 옮기는 것을 다시 검토한다.
