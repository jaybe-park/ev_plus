# 0034. 에퀴티 캐시 폐기 — 프리플랍 상수 테이블 + 실시간 계산, 정밀도 목표 ±0.5%p

- 대체: [0017](0017-equity-canonical-key-exact-protection.md), [0018](0018-equity-fast-paths.md)(캐시·DP 메모 부분), [0019](0019-equity-worker-priority.md), [0021](0021-equity-stats-incremental.md), [0022](0022-equity-cache-rebuildable-vsrandom-ui.md), [0032](0032-partial-index-only-for-pending-queues.md)

## 맥락
2026-09-26 전체 리뷰(self-reviews/2026-09-26.md RC5) 실측:
- `poker.db` 15GB 중 12.7GB가 `equity_cache`(1억 4천만 행)다. 행의 97%는 워커의 플랍 DP가 남긴 리버 부산물이다.
- 게임에서 같은 리버를 다시 만나는 비율은 0.06%다. 조회 적중률은 vs1 6~10%, 멀티웨이 ≈0%다.
- 적중 시 절약되는 시간은 판단당 2~9ms다. 리버 전수 계산은 3ms, 플랍 MC 2만 번은 0.14초다. "전수 계산은 분 단위라 미리 쌓아야 한다"는 원래 전제가 틀렸다.
- 턴/리버 순서를 보존한 키 때문에 같은 값이 중복 저장됐다. 증분 통계에 드리프트가 있었다. 멀티웨이 행은 동률 계산 오류로 무효다.

## 결정
`equity_cache`와 이를 채우는 워커를 폐기한다.
- **프리플랍:** 기존에 100만 번씩 계산해 둔 845개 값(169핸드 × 상대 1~5명)은 코드 상수 테이블로 옮긴다.
- **리버 상대 1명:** 전수 계산(990조합)을 모든 난이도에서 쓴다.
- **그 밖:** 실시간 몬테카를로로 계산한다.
- **정밀도 목표:** 봇·패널의 에퀴티는 표준오차 ±0.5%p(1σ) 이내다. 샘플 수는 이 목표에서 정한다(상대 수에 따라 약 1,000~2,000).
  - easy 난이도는 ADR 0014 "난이도 = 판단 해상도"대로 목표보다 적은 샘플을 의도적으로 쓸 수 있다.
- **제거 대상:** `equity_worker.py`의 캐시 채우기·스윕·증분 통계(`equity_cache_stats`)·대기 큐 부분 인덱스. 봇·패널의 캐시 기여도 끈다.
- **그라인드:** 봇 대결(아레나)만 남긴다.
- **vs_random UI:** 0022에서 결정한 "vs_random은 UI에서 빼고 vs_range만 표시"는 그대로 유효하다. vs_random 계산 자체는 봇 폴백·평가에 계속 쓴다.

## 버린 대안
- 부산물만 제거하고 플랍·턴 캐시 유지 — 적중률이 낮다는 근본 문제가 남고, 워커 유지비가 계속 든다.
- 부산물 제거 + 정수·집합 키 재설계 — 절약 시간(판단당 수 ms)에 비해 구현 비용이 가장 크다.
- 현행 유지 — 15GB와 워커 유지비가 남고, 그라인드를 켜면 시간당 0.4~1.8GB씩 다시 커진다.
