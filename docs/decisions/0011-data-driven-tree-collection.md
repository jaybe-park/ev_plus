# 0011. 데이터 기반 트리 수집(가정 금지, ε 분기, 도달확률 best-first)

- 상태: 유효
- 날짜: 2026-07-16 · 결정자: jaybe-park

## 맥락
가정에 기반한 열거로 트리 규모를 계산했더니 519,372 노드로 과다 계산됐고, 실제 브라우저 실측으로는 91,794로 바로잡혔다. "콜드콜 없음" 같은 규칙을 코드에 박아 넣는 방식은 틀린 것으로 드러났다. 무료 계정 수집 한도는 하루 100스팟이다.

## 결정
각 노드에서는 GTO Wizard가 실제로 보여주는 액션과 사이즈로만 가지를 뻗는다. 미리 어떤 액션이 있을지 가정하지 않는다. 레인지 합산 빈도가 ε(0.05%)를 넘는 액션만 확장한다(버튼이 있다는 이유만으로 분기하지 않는다). 확장 우선순위는 도달확률 가중 best-first이고, 트리 밖 스팟 큐는 보조 2순위(조상·자손 동시 수집)로 쓴다. 전체 트리 규모는 사전에 세지 않는다.

## 버린 대안
- 깊이 우선 BFS.
- 헤즈업 220노드 → 3-way 이하 2,665단계라는 사전 목표치(초기 결론) — 가정 기반 열거로 만든 수치라 데이터 기반 방식으로 대체됐다.
