# 0012. 수집 운영 안전장치 — 한도·환경오류·자격증명·지연

- 상태: 유효
- 날짜: 2026-07-17 (설계는 2026-07-08) · 결정자: jaybe-park

## 맥락
초기에는 화면 문구 키워드로 수집 한도를 추측하다 버그가 났다("Free accounts…" 문구는 한도와 무관하게 항상 떠 있다). 한도에 걸린 노드가 frontier·visited 어디에도 없이 유실된 적이 있었다. `--limit 200` 실행 중 크롬 렌더러가 크래시했는데(chrome://crashes로 확인, 서버 차단이 아님), 이 크래시로 실패한 84개 노드가 배지 데이터 이상(badSum)과 똑같이 취급돼 영구 실패로 기록될 뻔했다. 기계적으로 빠른 요청은 어뷰징으로 감지될 위험도 있었다.

## 결정
한도는 화면 상단 `X/100` 카운터를 파싱한 값만 유일한 신호로 삼고, 남은 여유가 안전마진(5) 이하면 다음 navigate 전에 안전 종료한다. 한도에 걸린 노드는 `frontier`로 되돌린다. 실측 사이즈는 히어로 Actions 패널(`[data-tst="study_action_btns"]`)에서만 읽는다(헤더의 다른 포지션 액션을 오인하는 `body` 전체 정규식은 쓰지 않는다). `is_env_failure()`로 크래시·타임아웃·저장 실패 같은 환경 오류를 badSum·핸드 0개 같은 데이터 이상과 구분한다. 환경 오류는 frontier로 되돌리고, 연속 2회면 탭을 재생성(로그인 유지)하며, 연속 6회면 안전 중단하고, 25노드마다 예방적으로 탭을 재생성한다. 수집은 사용자가 로그인해 둔 디버그 크롬(`--remote-debugging-port`, 별도 `--user-data-dir`)에 Playwright `connect_over_cdp`로 붙는다 — 자격증명 로그인은 대행하지 않고, GTO Wizard API를 직접 호출하는 것은 약관 리스크로 금지한다. 노드 사이에는 2~5초 균등 랜덤 지연을 둔다.

## 버린 대안
- 화면 문구 키워드로 한도 추측, `body.innerText` 전체 정규식 — 둘 다 오탐.
- 요청 지연만 늘려 크래시 대응 — 원인이 누적 메모리라 해결되지 않는다.
- Chrome MCP 수동 수집 유지 — 노드당 약 33초·3~6k 토큰이 들어 규모를 감당 못 한다.
- 브라우저 밖에서 GTO Wizard API 직접 호출 — 약관 리스크.
