# 0030. SQLite 유지, 서버형 DB(MySQL 등) 전환 반려

- 상태: 유효
- 날짜: 2026-07-08 (2026-07-17 재확인) · 결정자: jaybe-park

## 맥락
DB 용량 증가와 그라인드(아레나+워커 동시 실행) 중 쓰기 락 경합 문제로 MySQL/Docker 같은 서버형 DB로 전환할지 검토했다.

## 결정
로컬 단일 사용자, 프로세스 소수(웹 서버 + 워커 1개)인 현재 사용 패턴에는 SQLite + WAL이 적합한 영역이다. 서버형 DB로 옮기지 않고, 아래 트리거 중 하나가 실제로 발생하면 그때 파일 분리·보존·백업 등으로 대응한다: 파일 크기 5GB 도달, 락 경합 재발, RL 학습 파이프라인이 별도 저장소를 요구. 분석이 필요해지면 DuckDB/Parquet으로 내보내는 것으로 충분하다.

## 버린 대안
- MySQL/Docker 전환 — 운영 부담(컨테이너 관리, 백업, 접속 설정)이 이 프로젝트 규모의 이득보다 크다.

## 결과
- 영향받는 spec: `docs/spec/db.md`
- 강제 장치: 없음. 트리거 신호(5GB 등)를 넘겼는지는 사람이 주기적으로 확인해야 한다.
