# 0018. 에퀴티 계산 고속화 경로 — 계산용 평가기, 스트리트 분해 DP, 보드 중심 리버 테이블, PyPy

- 상태: 유효
- 날짜: 2026-07-08 · 결정자: jaybe-park

## 맥락
워커가 전수조사로 정확값을 채우는데, 7장 평가를 부분집합 브루트포스로 하면 플랍 1스팟에 수 분이 걸렸다. 같은 계산(같은 보드의 상대 조합, 턴·리버 자식)이 반복되는 구조도 활용하지 못하고 있었다.

## 결정
- **평가기 이원화**: 계산용은 랭크 카운트 + 수트 비트마스크로 직접 판정하는 `evaluate_rank()`를 쓰고, 쇼다운 표시용(best 5장)은 기존 `HandEvaluator.evaluate()`를 유지한다. 둘의 순위 판정은 같아야 한다.
- **스트리트 분해 DP**: 턴 정확값 = 리버 자식 46개의 합, 플랍 = 턴 자식 47개의 합. equity_cache가 메모 테이블이다(자식이 exact로 있으면 재사용, 없으면 계산해 저장). 결과는 직접 전수 열거와 완전히 같아야 한다.
- **보드 중심 리버 테이블**: 같은 5장 보드를 공유하는 리버 스팟들은 `board_rank_table`(보드 밖 2장 조합 1081개의 랭크 정렬표)을 한 번 만들고 이진탐색 + 내 홀카드 블로커 보정으로 990조합 값을 낸다. 턴·플랍 자식은 보드가 모두 달라 적용하지 않는다.
- 장시간 워커는 PyPy를 권장한다. PyPy `sqlite3`는 소비하지 않은 커서가 있으면 커밋을 거부하므로 DB 코드는 커서를 명시적으로 닫는다.

## 버린 대안
- 턴·플랍 자식에도 보드 테이블 적용 — 자식마다 보드가 달라 재사용 여지가 없음을 확인했다.
- 표시용 평가기까지 교체 — 반환 형식이 달라 UI·쇼다운 코드 영향이 크고 이득이 없다.
