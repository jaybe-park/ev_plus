# 0017. equity_cache 키 = 수트 정규화, exact 값은 보호, 레인지 조건부 equity는 저장하지 않는다

- 상태: 유효
- 날짜: 2026-07-07 · 결정자: jaybe-park

## 맥락
봇과 워커가 계산한 equity를 DB에 쌓아 재사용하려면 같은 스팟을 한 행으로 모아야 한다. A♥K♥/Q♥7♠2♦와 A♠K♠/Q♠7♦2♣는 수트만 바뀐 같은 스팟이다. 또 한 행에 MC 근사와 전수조사 정확값이 섞이면 정확값이 오염될 수 있고, 상대 레인지를 가정한 equity는 같은 카드라도 가정마다 값이 다르다.

## 결정
- 키는 `홀|플랍|턴|리버`이고, 24가지 수트 치환 중 사전순 최소 문자열을 대표로 쓴다. 홀과 플랍은 카드 순서 무관(정렬), 턴·리버는 스트리트 경계가 의미 있으므로 순서를 유지한다. 행은 `(spot_key, num_opponents)`로 유일하다.
- 값은 `wins/ties/total` 누적 카운트로 저장한다. MC 결과는 더해 가고, 전수조사 결과는 덮어쓰며 `exact=1`로 표시한다. **`exact=1`인 행에는 MC가 더해지지 않는다**(모든 누적 쓰기에 `WHERE exact = 0`).
- 레인지 조건부 equity(`ranged_equity`)는 조건부 분포이므로 equity_cache에 쓰지 않는다.

## 버린 대안
- 실제 카드 그대로 키 — 같은 스팟이 최대 24행으로 흩어져 재사용률이 떨어진다.
- 레인지 equity도 캐시(레인지 식별자를 키에 포함) — 레인지가 GTO 데이터·상황마다 바뀌어 적중률이 낮고 캐시만 커진다.
