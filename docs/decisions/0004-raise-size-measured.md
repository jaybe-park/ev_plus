# 0004. raise_size는 실측 bb(REAL), 공식은 폴백에만

- 상태: 유효
- 날짜: 2026-07-10~12 · 결정자: jaybe-park

## 맥락
3벳 사이즈가 포지션마다 3.2x/4.4x/5.4x로 제각각이라 배수 공식으로는 추론할 수 없었다. 그런데도 봇은 하드코딩 공식(오픈×3, 3벳×2.5)으로 사이즈를 추측하고 있었고, 저장 컬럼도 TEXT라 "3x" 같은 실측 아닌 값을 담고 있었다.

## 결정
`raise_size`를 TEXT에서 REAL(bb, raise-to 실측값)로 바꾼다. `ai/bot.py::_preflop_raise`는 실측값이 있으면 그것을 우선 쓰고, 없을 때만 공식을 쓰되 그 경로를 "폴백"이라고 코드에 명시한다. advisor는 문자열 플레이스홀더를 반환하지 않으며, 실측값 또는 `None` 둘 중 하나만 낸다.

## 버린 대안
- 배수 공식(오픈×3, 3벳×2.5 등) 유지 — 포지션별 실측과 어긋난다.

## 결과
- 영향받는 spec: `docs/spec/gto-preflop.md`, `docs/ai-bot.md`
- 강제 장치: 없음. `tests/test_grader.py:49`가 아직 `"raise_size": "2.5bb"` 문자열을 쓰고 있어 이 결정과 어긋난 채 남아 있다 — DECISIONS.md 참고.
