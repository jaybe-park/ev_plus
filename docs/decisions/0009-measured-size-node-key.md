# 0009. 저장 노드 키는 실측 사이즈 verbatim(깊이-캐노니컬 스냅 폐기)

- 상태: 유효
- 날짜: 2026-07-16 결정, 2026-07-17 구현 · 결정자: jaybe-park

## 맥락
이전 방식(깊이-캐노니컬 키, 예: 3벳=항상 R8)은 깊이별로 하드코딩한 사이즈를 저장 키와 런타임 키에 함께 써서 "항상 매칭"을 보장했다. 그 대가로 포지션별 실측 사이즈(11bb/13.5bb 등)가 뭉개졌고, 3벳+ 단계로 갈수록 URL이 화면과 어긋났으며, "추측 금지"(0002) 원칙과도 충돌했다. 깊이 기준을 택했던 원래 이유는, 사이즈가 가장 가까운 쪽으로 스냅하면 13.5bb 3벳이 4벳 17.5로 깊이가 잘못 분류될 수 있어서였다.

## 결정
저장 키의 레이즈 토큰은 화면에서 읽은 실측 raise-to 금액을 그대로 쓴다(예: `R13.5`). 하드코딩 캐노니컬 사이즈 테이블은 노드 키 생성 경로에서 빼고, 레거시 `situation_to_node_key` 전용으로만 격리한다. 깊이 오분류 문제는 형제 기반 런타임 스냅(0010)으로 넘겨 해결한다.

## 버린 대안
- 깊이-캐노니컬 키 유지 — 실측 뭉개짐, URL 결함, "추측 금지" 원칙 위반.
