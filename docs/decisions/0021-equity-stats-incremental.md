# 0021. `--status`는 증분 통계 테이블을 읽는다 — 모든 쓰기가 같은 트랜잭션에서 델타 반영

- 상태: 대체됨 → 0034
- 날짜: 2026-07-10 · 결정자: jaybe-park

## 맥락
`equity_worker.py --status`의 카테고리별 진행률이 equity_cache(당시 9,600만 행) 전체를 `GROUP BY`로 풀스캔해 59초 걸렸다. 커버링 인덱스로 6.8초까지 줄일 수 있었지만 테이블이 계속 커지므로 다시 느려진다.

## 결정
`(street, num_opponents)`별 `spots / exact_done / total_sum` 요약 테이블 `equity_cache_stats`를 두고, equity_cache에 쓰는 **모든 경로**(봇 MC 기여, 봇 exact 기여, 워커 스팟 등록·exact 승격·MC 누적·DP 자식 저장)가 같은 트랜잭션 안에서 `bump_equity_stats`로 델타를 반영한다. 델타는 "썼다고 가정"하지 않고 쓰기 전후 실제 상태를 비교해 계산한다(다른 프로세스가 먼저 처리해 건너뛴 행은 0). 한 배치 안에 같은 정규화 키가 여러 번 나오면 마지막 값 하나로만 계산한다 — 이 규칙이 없어서 실제로 드리프트가 났다. `--rebuild-stats`는 풀스캔으로 다시 채우는 백필·복구용이다.

## 버린 대안
- 커버링 인덱스 — 테이블 성장에 따라 다시 느려진다.
- 주기적 재집계 — 풀스캔 비용이 그대로이고 그 사이 값이 틀린다.

## 결과
- 영향받는 spec: `docs/spec/equity.md`
- 강제 장치: 없음 — 드리프트 사고가 한 번 있었다. 새 쓰기 경로를 추가할 때 델타를 빠뜨리면 조용히 틀린다.
