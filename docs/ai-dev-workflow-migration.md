# 기존 프로젝트를 AI 개발 운영 플레이북 구조로 옮기기

> **목적**: 문서가 이미 쌓인 기존 저장소를 [ai-dev-workflow-playbook.md](ai-dev-workflow-playbook.md)의 구조(현재 상태 spec / 결정 ADR / 이력 git, 결정 대기열, 기계적 강제 장치)로 **한 번** 옮기는 절차.
> **수명**: 일회성 문서다. 이관이 끝나면(§8 완료 조건) 그 프로젝트에서는 더 필요 없다 — 복사해 뒀다면 이관 완료 커밋에서 지운다.
> **빈 프로젝트**는 이 문서가 필요 없다. 플레이북 §8만 따른다.

---

## 1. 원칙

- **한 번에 옮기지 않는다.** 도메인 하나로 시범 → 잘 돌면 확산. 한꺼번에 옮기면 사람이 검토할 양이 감당되지 않고, 옮기는 동안 모순이 새로 생긴다.
- **옮기는 동안에도 새 누적은 멈춘다.** 이관 시작 시점부터 완료 Task를 archive에 더 쌓지 않는다(TODO에서 지우기만, 남길 판단은 ADR로).
- **모순을 발견하면 에이전트가 고르지 않는다.** 사람에게 묻고, 답을 ADR로 확정한다. 기존 문서끼리 다르게 말하는 곳은 이관의 가장 값진 산출물이다.
- **삭제는 추출 뒤에.** git이 이력을 보존하므로 삭제 자체는 안전하지만, 근거를 추출하지 않고 지우면 사실상 찾을 수 없게 된다.

---

## 2. 준비

1. 플레이북을 저장소에 복사한다(`docs/ai-dev-workflow-playbook.md`).
2. 플레이북 §3 폴더를 만든다(`docs/spec/`, `docs/decisions/README.md`, `DECISIONS.md`).
3. 플레이북 §9를 보고 **프로젝트 값**을 정해 `CLAUDE.md`에 적는다.
4. ADR `0001-adopt-playbook.md` — 도입 이유, 조정한 기본값, 이관 순서(어느 도메인부터).
5. `CLAUDE.md` 문서 지도에 "이관 중 — 이관 완료 도메인은 `docs/spec/`, 미완료 도메인은 기존 문서"를 명시한다.

---

## 3. 결정 대기 통합

memo·TODO·archive·각종 문서에 흩어진 "사람 결정 필요" 항목을 `DECISIONS.md` 하나로 모은다.

- 형식: `D-NN | 무엇을 정해야 하나 | 선택지(★추천) | 안 정하면 무슨 일이 생기나 | 막고 있는 Task`
- 원래 자리에는 "→ DECISIONS.md D-NN" 한 줄만 남긴다.
- 이미 결정됐는데 문서에 반영 안 된 것(대화로만 결정된 것 등)은 결정 대기가 아니라 **바로 ADR**로 쓴다.
- 모은 뒤 WIP 한도를 넘으면 이관보다 **결정 세션을 먼저** 한다.

---

## 4. 시범 도메인 전환

가장 자주 바뀌거나, 문서 모순이 가장 많은 도메인 하나를 고른다.

1. **spec 새로 쓰기** — 기존 요구사항·설계 문서에서 "지금 유효한 규칙"만 뽑아 `docs/spec/<domain>.md`를 새로 쓴다. 기존 문서를 고쳐 쓰지 말고 새로 쓴다(정정 서술을 끌고 오지 않기 위해).
2. **ADR 추출** — 서술 속에 묻힌 결정을 ADR로 뽑는다(결정마다 반 페이지). 뒤집힌 결정은 옛 ADR(대체됨) + 새 ADR 쌍으로 쓰되, 옛 것은 뒤집힌 이유가 앞으로도 중요할 때만 남긴다.
3. **모순 해소** — 문서끼리, 문서와 코드가 다르게 말하는 곳을 목록으로 만들어 사람에게 묻고 ADR로 확정한다. "코드가 맞다"를 기본으로 가정하지 않는다 — 코드가 원칙을 조용히 깬 경우가 흔하다.
4. **원칙 테스트** — spec의 절대 규칙마다 강제 장치(테스트)가 있는지 확인하고, 없으면 만든다. spec 규칙 옆에 테스트 이름을 적는다.
5. **옛 문서 정리** — 옮긴 부분은 옛 문서에서 지우고 "→ docs/spec/<domain>.md로 이동" 한 줄만 남긴다.
6. **시범 기간** — 한두 주 동안 이 도메인의 Task를 새 구조로 진행해 보고, 템플릿·프로젝트 값을 조정한다(조정은 ADR로).

---

## 5. 확산

시범이 잘 돌면 나머지 도메인을 같은 절차(§4)로 하나씩 옮긴다. 도메인마다 커밋을 나눈다 — 문제가 생기면 그 도메인만 되돌릴 수 있게.

---

## 6. 규칙 이관

전역 설정(`~/.claude/CLAUDE.md`, 개인 스킬 등)에 있던 **프로젝트 규칙**을 저장소로 옮긴다(플레이북 §7).

- 저장소 `CLAUDE.md`가 "전역 규칙을 그대로 따른다"고 링크하는 곳을 찾아, 그 내용을 저장소 안으로 가져온다.
- 반복 절차(정기 리뷰, 자율 진행 등)는 `.claude/skills/`로, 역할별 서브에이전트는 `.claude/agents/`로.
- 기존에 같은 목적의 스킬이 이미 있으면 새로 만들지 말고 **통합**한다(중복 스킬은 두 곳의 진실이 된다).
- 전역에는 개인 취향만 남긴다.
- 반복된 사고의 재발 방지 문장은 hook·테스트로 바꾼다(플레이북 §6).

---

## 7. archive 처리 — 결정 추출 → 참조 정리 → 삭제

완료 작업을 누적해 온 archive 파일(예: `TODO-archive.md`, `CHANGELOG`식 작업 기록)은 **동결이 아니라 삭제**한다. "읽지 말 것" 경고는 문장 규칙이라 검색 결과에 계속 섞이고, 에이전트는 결국 그것을 현재 규칙으로 읽는다.

**순서가 중요하다.**

1. **결정 추출** — archive 안의 "왜 이렇게 했나" 중 **지금도 유효한 것**을 ADR로 옮긴다. 도메인별 spec 전환(§4·§5)을 하면서 그 도메인 부분을 함께 추출하면 효율적이다. 이미 뒤집혀 의미가 없어진 경위는 옮기지 않는다(git에 남아 있다).
2. **참조 정리** — 다른 문서·코드 주석·테스트가 archive를 가리키는 곳을 찾아 바꾼다.
   - 찾기: archive 파일 이름, archive 안의 작업 ID(예: `T-xxx`)로 저장소 전체를 검색한다.
   - 바꾸기: 해당 ADR 링크로. ADR이 없고 단순 경위라면 커밋 해시로, 가치가 없으면 참조 자체를 지운다.
   - 작업 ID가 코드 주석에 수백 곳 퍼져 있다면, 한 번에 다 바꾸려 하지 말고 "ADR로 바뀐 것만 바꾸고 나머지 ID 언급은 지운다"로 단순화한다.
3. **삭제** — 파일을 지우고 커밋 메시지에 복구 방법을 남긴다:
   ```
   TODO-archive.md 삭제 — 유효한 결정은 docs/decisions/로 이관 완료
   이전 내용: git show <삭제 직전 커밋 해시>:TODO-archive.md
   ```
4. **재발 방지** — 이후 완료 Task는 TODO에서 지우기만 한다. 플레이북 §8.1 점검 신호("누적 기록 파일이 생겼는가")로 확인한다.

> archive가 작으면(수십 줄) 1·2번이 금방 끝나니 이관 초기에 바로 지워도 된다. 크면 도메인 전환과 함께 한 도메인씩 추출하고, **마지막 도메인이 끝난 뒤** 지운다.

---

## 8. 이관 완료 조건

아래가 모두 참이면 이관이 끝난 것이다. 이 문서를 저장소에서 지우고 이후는 플레이북만 따른다.

- [ ] 모든 도메인이 `docs/spec/`에 있고, 옛 요구사항·설계 문서는 삭제됐거나 "이동" 한 줄만 남았다
- [ ] 결정 대기가 `DECISIONS.md` 한 곳에만 있다
- [ ] archive 파일이 삭제됐고, 저장소 어디에도 그것을 가리키는 참조가 없다
- [ ] 저장소 `CLAUDE.md`가 전역 규칙에 의존하지 않는다
- [ ] spec의 절대 규칙마다 강제 장치가 적혀 있다(없으면 "장치 없음"이라고 명시)
- [ ] 에이전트가 매 세션 읽는 필수 문서가 프로젝트 값(기본 1만 토큰) 이내다
